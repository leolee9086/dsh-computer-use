# 源语义树一致性：反例与提供者接入条件

当前生产实现提供固定结果分页和有界采集变化恢复。本文独立记录额外的源事务保证：可运行反例说明哪些通用读取证据不足，以及合作来源协议必须满足的条件。测试窗口的两字段带锁导出是一个原型，未接入生产窗口全树能力。通用桌面自动化无需以该协议为前置条件。

## 已验证的反例

自建 Windows 提供者有两个互斥状态，整个状态由同一把锁保护：

| 源状态 | 节点12的名称 | 节点13的名称 |
| --- | --- | --- |
| A | Pair left active | Pair right idle |
| B | Pair left idle | Pair right active |

读取节点12的名称时，提供者静默切换到 A；读取节点13时切换到 B。其他摘要字段、节点身份和结构保持不变。切换不发送 UIA/MSAA 事件。不存在两个节点同时 active 的源状态。

生产采集器的第一遍和完整复读却都得到 `Pair left active`、`Pair right active`。真实 UIA 和 MSAA 均接受并封存这一组合；查询的两行分页保持相同结果 ID/摘要，后续页原生采集调用为零。两者仍报告 `source_atomic:false`，覆盖 complete 也没有改变这个字段。UIA 覆盖39节点，MSAA覆盖33节点，均完整复读覆盖范围，包括查询未命中节点。

测试源为每次状态切换累加版本号。在该实验中版本从 `0` 增到 `6`。同一来源代次的可靠版本检查能发现这种往返变化；内容哈希和任意有限轮相符读取不能替代它。测试还提供一个同时持有源锁的两字段导出，每次导出都符合上述互斥不变量。

首次实验使用深度2，UIA窗口装饰层使覆盖为partial。随后改用深度20，完成这个小窗口的全部覆盖后复现相同组合。这项覆盖修正没有改变生产实现。

从仓库运行：

```powershell
node test/win32-semantic-source-consistency-smoke.mjs
pnpm run smoke:electron "C:\path\to\DeepSeek Harness.exe"
```

测试直接使用生产 WindowsComputer、原生 C# 工作进程、官方 Cordis 本地子进程服务和 ManagedRunner。共享测试提供者默认关闭此模式；只在 `pair_enable` 后启用。重新启用会更换来源代次后重置版本号，避免同一代次内版本倒退。测试不会修改其他应用、系统时钟或生产能力字段。

## 合作提供者所需的合同

优先接入源程序提供的不可变语义树导出。源程序在保护所有相关写入的锁、UI事务或MVCC版本中复制请求范围的身份、父子顺序、摘要字段和查询未命中节点，随后在锁外序列化这份不可变副本。分段传输读同一副本。一次 RPC 或 UI 线程执行本身不等于事务；源程序的其他写入线程也必须参加同一协议。

| 提供者返回的证据 | 必须满足的条件 |
| --- | --- |
| 来源身份 | HWND/PID、进程生命周期、原生根身份和提供者代次对应已选择的窗口；重启或版本重置更换代次，不能仅用可复用PID/版本号 |
| 快照身份与切点 | 同一来源代次中唯一的快照ID/版本，指出导出范围和原子切点；后续页访问同一不可变副本 |
| 覆盖范围 | 明确root/scope/depth、已覆盖节点和顺序、预算截断、虚拟化未实现项；局部快照不能代表其他进程或提供者的全树 |
| 数据与查询 | 所有交付字段属于同一源版本；先建立同版本覆盖，再筛选查询，未命中项不能绕过版本约束 |
| 资源与生命周期 | 保留现有节点/字节/进程池预算和单调时效；传输、排队及提供者执行共用工具截止；取消或到期释放源副本和本地代次 |
| 原生动作绑定 | 导出身份可以精确关联原生目标；动作仍按当前窗口/提供者代次和目标身份校验，历史快照不能直接获得或恢复动作权限 |

另一条可用路径是提供者的可靠版本协议：读开始stamp，读取范围，再读结束stamp；两个stamp必须属于同一来源代次、同一范围、相同的已提交版本。写入开始前发布“写入中”，结束后发布新的提交版本；任何字段、顺序、插删或往返恢复都推进版本。版本不能在同一代次内回绕，stamp需要原子读取及明确的内存顺序。

这个版本协议还有两个必要条件：所有相关写入都被计入，所有读取都来自该版本保护的数据源。若 UIA/MSAA 层可返回未参与协议的旧缓存、来自其他进程的子树，或数据与stamp的更新顺序不一致，仅在外层多读一个计数器仍不能证明原子性。可使用带版本的逐节点读取或版本化导出解决；普通事件计数器不满足这份合同。

适配器应由选定应用或提供者的实际接口决定。生产路由目前没有接入上述协议；本文件不是已经可调用的工具schema或能力声明。接入后，仅在匹配来源、完整验收通过的请求上报告源原子保证。要求源原子性的请求遇到不支持的来源、协议失败或版本变化时，应在交付元素前返回明确失败；继续使用其他一致性模式需要明确选择。

## 接入后的完成验收

- 普通第三方 UIA/MSAA 窗口继续正确报告其支持范围，不能因安装一个合作适配器而获得全局源原子保证。
- 往返属性变化、等节点数重排、插删、查询未命中项变更和跨进程子树变化，均不能混入已接受的源版本。
- 带锁或版本化导出的快照符合源不变量；运行中的变更不改变其后续页。
- 不支持的来源、重启/代次变化、过期、损坏身份、字节/节点上限、取消和阻塞均有有界结果，未交付的失败代次不能续取。
- 来源原子性与 coverage、固定结果分页、原生动作实时有效性分别验证。
- 在目标应用的实际接口、Windows/Electron和工具运行时完成验收，再更新生产能力、版本、交付记录并推送。

通用桌面自动化继续使用普通 UIA/MSAA 接口：按范围和条件取缓存字段，在截止内重新定位失效的只读采集，固定结果分页与动作的实时身份校验分别处理，无需先修改目标应用。实现对照见[成熟桌面自动化源码](DESKTOP-AUTOMATION-IMPLEMENTATIONS.md)。上述合作协议只适用于额外的源事务保证；不能将它当作继续修复通用采集的前置条件。

## 已核实的公开合同

[Microsoft：Caching in UI Automation Clients](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/caching-in-ui-automation-clients) 将缓存定义为预取数据，说明缓存仅在UI没有变化时有效，并由客户端更新。它支持减少跨进程调用和保留已取得数据；这份合同没有提供覆盖全部写入线程的源事务。上述原生反例直接验证当前采集路径仍存在这个差异。

[Microsoft：CoreAutomationRemoteOperation](https://learn.microsoft.com/en-us/uwp/api/windows.ui.uiautomation.core.coreautomationremoteoperation?view=winrt-26100) 将远程操作的作用说明为避免过多跨进程调用、降低通信延迟，公开成员用于导入对象、执行字节码和取得结果。已核实的这份接口文档没有承诺全树事务性；批处理或把读取搬到另一进程本身不足以升级为源原子保证。
