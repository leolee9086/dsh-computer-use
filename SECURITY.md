# Security and Operating Boundary

## Authority

The host provider can observe and control the active local desktop. It never opens a remote-control listener, accepts a remote desktop endpoint, or starts an automation action without a model tool call. Every system command is launched through DSH's managed subprocess service with a configured deadline, output cap, process-tree cancellation, and private temporary-file cleanup.

## Image Handling

A screenshot is captured directly as PNG bytes. The provider does not use the system clipboard, Rubick's `ScreenCapture.exe`, an Electron runtime, or an opaque native binary. Before publishing an image attachment, `computer_screenshot` verifies that the current model route explicitly supports image input.

The returned screenshot ID is scoped to the calling agent, retained in memory only, bounded per agent, and expires after `maxObservationAgeMs`. Each result includes a SHA-256 hash of the persisted image attachment bytes after DSH normalization. Pointer coordinates are rejected outside the exact persisted attachment dimensions, translated through the saved native desktop rectangle, and clamped to that rectangle's last physical pixel. A later model step cannot reuse an image ID from another agent or a stale screen state.

## Input Handling

All pointer, keyboard, window-focus, and semantic-element calls are exclusive tool calls. `computer_windows:list` produces short-lived agent-scoped `window_id` values, and every successful control action consumes every screenshot, semantic, and window-list record for that agent. The next consequential action must start from a new observation. Windows input goes through the bundled native helper (`native/dsh-screen.exe`, Rust): it sets DPI awareness before coordinate-sensitive APIs, sends Unicode with `SendInput`, and always releases the mouse button even when a drag fails partway. Window focus first uses the normal foreground request; when Windows foreground-lock rules reject it, the helper sends one isolated Alt press/release (it produces no character) and retries, then falls back to temporarily attaching only the helper, foreground, and target input queues — and it verifies the resulting foreground handle, reporting failure instead of pretending focus succeeded. Semantic (UI Automation) actions run in-process through a small C# bridge (`src/windows-uia.cs`, loaded by edge-js) instead of spawning a script interpreter; it re-locates the element by runtime ID and re-checks its identity before acting.

A semantic snapshot can be captured only against a fresh screenshot ID; it records that exact ID and the persisted attachment SHA-256 hash. A semantic action must name the same fresh screenshot and a fresh accessibility snapshot, so separately fresh but mismatched evidence is rejected. Each native provider re-resolves an observed element before action and checks process plus available current identity metadata; Windows checks UIA runtime ID plus automation ID/name/class/role through a bounded control-view traversal, Linux checks AT-SPI path plus process/identity, and macOS checks AX path plus PID/name/role and observed bounds when present. No semantic action falls back to a coordinate click. `scroll_into_view` is allowed only for an observed offscreen element with the required native capability, and always requires renewed screenshot and semantic evidence afterward.

`observeApproval` and `controlApproval` each support `ask`, `allow`, and `deny`. The installable bundle activates the tool package with both values set to `ask`; a profile patch can override either row only by restating that row's complete config because Loader layers replace config values instead of deep-merging them. A local `deny` is resolved before downstream approval listeners and repeated as a final monotonic guard. Default `ask` inherits `danger-full-access` only when the authoritative `permissionPresets` service resolves the current agent's preset to both `sandbox: danger-full-access` and `approval: never`; absent, malformed, unknown, or custom permission state remains an ask. When a pre-execution listener short-circuits an ordinary local `ask`, the tool body requests approval through the same DSH approval service before it reaches the desktop provider. Use `deny` to remove an operation class, or `ask` when the host has an interactive approval flow.

## Platform Coverage

Windows is the full locally verified provider: direct PNG capture, multi-display physical coordinates, pointer/keyboard, visible non-minimized top-level window control, bounded UI Automation snapshots rooted at the focused application window, semantic lookup, and pattern-based actions including scroll-into-view. Snapshot output uses a small `maxAccessibilityNodes` cap, while a separate finite `maxAccessibilityActionCandidates` cap bounds the control-view traversal used for action-time re-identification. macOS supports direct capture, keyboard automation, System Events window listing/focus with PID/title/bounds and a required native-window-ID re-identification before and after process foregrounding, and AX semantic snapshot/action through bundled JXA; pointer actions use the bundled CoreGraphics JXA helper and Accessibility permission. Linux supports capture through `grim`, `gnome-screenshot`, or ImageMagick; pointer/keyboard/window commands require `xdotool` and therefore an X11-compatible session, while semantic snapshot/action requires `python3`/`python`, `pyatspi`, and an active AT-SPI bus. Linux window focus rechecks the listed XID metadata immediately before activation and verifies that the XID becomes active afterward; its AT-SPI helper lazily enumerates only configured node/candidate budgets and rejects action paths deeper than the snapshot limit. macOS and Linux adapters surface missing command or permission failures explicitly. Native runtime proof for those two adapters remains required on their target operating systems, including macOS multi-monitor capture-origin validation.

## Sensitive Screen Content

A desktop screenshot can contain credentials, personal data, and other information visible on screen. The image becomes a DSH attachment and is supplied to the selected model route. Treat the selected model provider and its retention policy as part of the desktop-control trust decision.
